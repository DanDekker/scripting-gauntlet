# 152-lua-utf8-chars

> "Our line-length dashboard counts bytes, so every line with an accent looks 50% longer
> than it is. One file also has a corrupt byte in it and nobody noticed."

## Input

`in/mixed.txt` — a text file with one line per record. Most lines are ordinary UTF-8
text; some carry accented letters, CJK characters or an emoji. **One line contains a byte
that is not valid UTF-8** and has to be detected rather than silently mangled.

The file is generated by a setup script because a corrupt byte cannot be committed as
text.

## Rules

1. Read the file as **bytes**. Split it into lines on `\n`. A newline at the end of the
   file does not create an extra line.
2. Lines are numbered by their 1-based position in the file. An **empty** line is ignored:
   it produces no row and is not counted anywhere, but it still consumes its position.
3. A line is **valid** when its bytes decode as UTF-8. An invalid line is skipped: it
   produces no row, and none of its bytes count toward any total.
4. For a valid line, report:
   - `chars` — the number of **characters** (code points), not bytes;
   - `bytes` — the number of bytes;
   - `head` — the first **10 characters** of the line. When the line has more than 10
     characters, cut it after the tenth character without splitting a multi-byte
     character. A line with 10 or fewer characters is reported whole.
5. `chars` and `bytes` are counted over the **valid** lines only.

## Output

Write exactly these files to `$OUT`:

1. **`out/chars.csv`** — header `line,chars,bytes,head`, then one row per valid line, in
   file order. `head` is written in UTF-8; a field containing a comma, a double quote or
   a newline is written in double quotes with any inner double quote doubled.
2. **`out/summary.json`** — an object with exactly these keys:
   - `lines` — how many lines the file has, including the invalid and empty ones (int)
   - `valid` — how many lines were valid (int)
   - `invalid` — how many lines were not valid UTF-8 (int)
   - `chars` — the total character count over the valid lines (int)
   - `bytes` — the total byte count over the valid lines (int)

   Print it as one compact JSON object: `{"lines":7,"valid":6,...}`.

## Messes to expect

- `café` is 4 characters and 5 bytes; `日本語` is 3 characters and 9 bytes
- the emoji is one character and four bytes
- one line has a raw `0xFF` byte in the middle of it: it is the invalid line, and its
  bytes must not appear in the totals
- one line is longer than 10 characters and is cut mid-line, but never mid-character

## Timebox

Four minutes. The `utf8` library in the standard library does all of it; do not write a
decoder by hand.
